## Рекомендации по улучшению постановки задачи

### 1. Добавить структурированное описание проблемы

```markdown
## Проблема

В MnemoForge есть два разных типа сущностей: improvements (улучшения) и tasks (задачи).

### Текущие проблемы:
1. **Разные идентификаторы и хранилища**
   - Improvements: UUID в improvements.db
   - Tasks: UUID в project_tasks.db
   - Связь только через task.linked_improvement_id

2. **Разные паттерны доступа**
   - list_improvements() → improvements
   - list_tasks() → tasks
   - Нет единого API

3. **Отсутствие синхронизации статусов**
   - Improvement resolved → task не меняет статус
   - Task reopened → improvement не меняет статус

4. **Разные MCP endpoints**
   - list_improvements - только improvements
   - memory_get - только memories
```

### 2. Добавить Definition of Done

```markdown
## Критерии готовности (Definition of Done)

1. ✅ get_artifact(artifact_key) работает для improvements
2. ✅ get_artifact(artifact_key) работает для tasks
3. ✅ list_artifacts() возвращает смешанный список
4. ✅ Синхронизация improvement→task работает
5. ✅ Синхронизация task→improvement работает
6. ✅ Backfill заполняет связи для существующих данных
7. ✅ Все существующие тесты проходят
8. ✅ Новые тесты покрывают унифицированный доступ
9. ✅ MCP tools работают с унифицированным API
10. ✅ Документация обновлена
```

### 3. Добавить MVP определение

```markdown
## MVP (Минимально жизнеспособный продукт)

Фаза 1-2:
- UnifiedArtifactService с get_artifact()
- list_artifacts() с базовой фильтрацией
- Без синхронизации статусов

Фаза 3-4:
- Синхронизация статусов
- Backfill для существующих данных
```

### 4. Добавить Edge Cases

```markdown
## Edge Cases

1. **Множественные связи**
   - Improvement связан с несколькими tasks?
   - Решение: 1:1 связь, множественные не поддерживаются

2. **Отсутствие связи**
   - Task без linked_improvement_id?
   - Решение: Работает автономно

3. **Конфликт статусов**
   - Одновременное изменение?
   - Решение: Приоритет последнего изменения

4. **Удаление**
   - Удаление improvement при наличии task?
   - Решение: Каскадное удаление или soft delete
```

### 5. Добавить требования к производительности

```markdown
## Требования к производительности

- get_artifact() < 50ms (p95)
- list_artifacts(limit=50) < 100ms (p95)
- Синхронизация статусов < 200ms (p95)
- Backfill (1000 записей) < 10s
```

### 6. Добавить rollback стратегию

```markdown
## Rollback стратегия

1. **Database migrations**
   - Использовать reversible migrations
   - Сохранять backup перед миграцией

2. **Code rollback**
   - Feature flags для новых endpoints
   - Graceful degradation при ошибках

3. **Data recovery**
   - Backfill с dry-run режимом
   - Восстановление из backup при ошибке
```

### 7. Добавить roll-out стратегию

```markdown
## Roll-out стратегия

1. **Phase 1: Canary** (10% traffic)
   - Включить feature flag для 10% пользователей
   - Мониторинг метрик и ошибок

2. **Phase 2: Gradual** (50% traffic)
   - Увеличить до 50% при отсутствии проблем
   - Продолжить мониторинг

3. **Phase 3: Full** (100% traffic)
   - Полный roll-out
   - Удаление legacy endpoints через 2 недели
```
